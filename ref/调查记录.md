# Windows CPU 指示器设计调查

调查日期：2026-11-20  
目标项目：Windows x64 轻量级总体 CPU 托盘指示器

## 调查范围

- Windows 自带任务管理器相关的公开设计信息与 CPU 采样 API。
- Windows 开源进程/系统监控工具。
- 开源托盘 CPU/系统负荷指示器的菜单、图标呈现、资源开销和可选功能设计。

## 主要发现

### Windows 任务管理器与调度优先级

Windows 公共文档以 Task List（任务列表）作为高优先级进程的示例，表示这类界面需要在系统繁忙时保持响应；但同一文档警告，高优先级程序长时间运行可能使其他线程无法获得 CPU。对周期性更新显示的监视程序，文档通常建议使用空闲优先级；若采用高优先级，应让线程只在短时间内执行，并在间隔期间阻塞等待。

本项目用户明确要求 `HIGH_PRIORITY_CLASS`。因此实现应保持高进程优先级、避免实时优先级，且不可使用忙循环；需在后续验证中同时测刷新延迟、程序自身 CPU 和系统交互响应。

### 总体 CPU 采样

Windows `GetSystemTimes` 返回系统空闲、内核、用户时间，单位为 100 纳秒时间刻度。多处理器系统的值是处理器时间总和（超过 64 个处理器时与处理器组有关）。可对两个采样时刻的时间差计算总体忙碌率；通常以总时间差减去空闲时间差作为忙碌时间。

### 开源项目比较

| 项目 | 公开设计信息 | 对本项目的参考 |
|---|---|---|
| System Informer | 开源的多用途系统资源监视、调试和进程工具 | 可作为进程信息功能的参考；其功能规模远超本项目，不宜复用整体架构。 |
| TrafficMonitor | Windows CPU、内存、网络监控；托盘/任务栏显示，右键菜单及硬件监控选项；其文档提示硬件监控可能增加 CPU 和内存开销 | 将核心指标和可选高开销功能分开；用菜单控制是否开启进程排名及日志。 |
| glint | 托盘实时条形指示，多指标可由右键勾选；公开报告约 200 KB EXE、6.2 MB 私有内存、隐藏窗口 CPU 使用约为一个核心的 0.05%–0.4% | 条形托盘图标和勾选菜单符合交互方向；这些公开数字不满足本项目的体积/私有内存目标，且无法直接横向比较测试环境。 |

## 设计建议

1. 首版采用原生 C 和 Win32 API，避免大型框架/运行时；目标架构为 x64。
2. 用 `GetSystemTimes` 计算总体 CPU；周期性更新托盘图标，低负荷时放慢更新间隔。
3. 右键菜单提供进程排名、日志、自启动等勾选项；进程排名或日志关闭时不执行对应工作。
4. 高优先级线程只短暂采样、绘制、处理菜单，然后阻塞等待计时器；避免忙等。
5. 以实际构建和运行测量 EXE 大小、私有内存、CPU 时间及系统繁忙时的更新时间。开源项目自报数值只能作参照，不视为本项目的验收证据。
